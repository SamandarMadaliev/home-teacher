# Home Teacher — agent / continuity notes

This file is the **tracked** copy of project context for new chats (`.cursor/rules/` may be gitignored locally). Point the AI here or keep this open for handoff.

## What this app is

Local **Laravel** app to watch **course videos from disk** with **saved progress** (SQLite). Assumed **single-user / local** unless you add auth.

## Stack

- Laravel (Blade), SQLite, Vite
- **Plyr** — `resources/js/player.js` (Vite entry `player`)
- CSS: `resources/css/app.css` (e.g. `.courses-grid`, theater mode, Plyr overrides)

## Data model (short)

- **Course** — `title`, `folder_path`; has many **Video** (`sort_order`)
- **Video** — a "lesson"; `type` ∈ {`video`, `pdf`, `html`} (`Video::TYPE_*`), set by `CourseVideoScanner` from the file extension. `video` lessons play in Plyr and track position; `pdf`/`html` lessons render in an iframe on the watch page (`videos/show.blade.php` branches on `$video->isVideo()/isPdf()/isHtml()`) and have no play position — completion is a manual "Mark as done" toggle (`videos.mark-complete` route, `VideoProgressService::setManualCompletion()`). HTML lessons are framed with `sandbox="allow-scripts"` (no `allow-same-origin`) since the file's own script could otherwise run with the viewer's session — do not drop that attribute.
- **VideoProgress** — per-lesson watch state; `progressPercent()` powers bars (for manual-completion lessons this is just 0 or 100, no duration)
- **VideoNote** — `body`, optional `timestamp_seconds` (lesson notes vs time cues)
- **VideoAttachment** — file or link resource per lesson; `kind` ∈ {`file`, `link`}, `title`, `url` (links), `file_path`/`mime_type`/`size_bytes` (files), `sort_order`. **Files are referenced, not uploaded** — `file_path` is either an absolute path or a path relative to the parent course's `folder_path`, mirroring how videos work. `VideoAttachment::absoluteFilePath()` resolves it safely (no traversal, must be a real file). Deleting an attachment row leaves the original file on disk untouched.

## Routes worth knowing

- Courses: `courses.index`, `courses.show`, `courses.create`, `courses.store`, `courses.rescan`, `courses.videos.reorder` (POST JSON `{ video_ids: number[] }` — full permutation of that course’s lessons)
- Videos: `videos.show`, `videos.update` (PATCH — rename lesson), `videos.stream`, `videos.progress` (POST JSON, video lessons only), `videos.mark-complete` (POST JSON `{ completed: bool }`, pdf/html lessons)
- Notes: `videos.notes.store` (POST JSON `{ body, timestamp_seconds? }` → `{ message, note: { id, html } }` — watch page saves via fetch, no reload), `videos.notes.destroy`, `videos.notes.preview` (POST JSON `{ body }` → `{ html }` — Preview toolbar)
- Profile: `profile.account`, `profile.analytics` (watch stats / monthly activity), `profile.notes`, `profile.accent.update`
- Attachments: `videos.attachments.store` (POST, `kind=file|link`; for files send a `file_path` string — absolute or relative to the course folder; for links send `url`), `videos.attachments.download` (GET — streams the file inline from its real on-disk location via `response()->file()`), `videos.attachments.destroy`
- Playground: `playground.show` (GET — picks up detected runtimes via `LanguageRuntimeProbe`), `playground.run` (POST JSON `{ language, code, stdin? }` → JSON `{ stdout, stderr, exit_code, duration_ms, timed_out, stdout_truncated, stderr_truncated }`), `playground.refresh` (POST — clears the probe cache).
- Problems: `problems.*` resource routes (index/create/store/show/edit/update/destroy; index takes `q`, `status`=todo|attempted|solved, `difficulty`, `tag`, `sort`), `problems.random` (GET — redirects to a random unsolved problem), `problems.preview` (POST `{ body }` → `{ html }`, statement markdown preview), `problems.reference-check` (POST `{ language, code, compare_mode?, time_limit_ms?, tests[] }` → **NDJSON** stream of per-case results for the author's *unsaved* form), `problems.run` (POST JSON `{ language, code, stdin? }` → raw run result, no verdict), `problems.run-examples` (POST — **NDJSON** stream over visible cases only, records nothing), `problems.submit` (POST — **NDJSON** stream `start` / `case`* / `done`; records a `ProblemSubmission`), `problems.submissions.show` (GET JSON incl. code). Run/submit/reference routes are throttled.

## Features (do not break casually)

1. **Course index**: cards show **overall progress** — `Course::aggregateProgressPercent()`. List is ordered by **most recent watch activity** (`max(video_progress.updated_at)` per course), then courses with no watch history by title.
2. **Course show** (`/courses/{course}`): **course-wide progress bar** + per-lesson list with **drag handle** to reorder (Sortable.js); **rescan** adds/removes lessons from disk without changing **custom lesson names** you set (scanner only sets titles for newly discovered files); new files append at the end. Current/next lesson use **index order**, not raw `sort_order` gaps.
3. **Video page**: Plyr, theater (`T`), keyboard shortcuts; **Previous / Next lesson** cards **always** shown; **disabled** style on first/last; neighbors by **order index**, not only `sort_order` gaps.
4. **Lesson notes** under the player: general vs **playhead time**; list shows cues that **seek** — `window.__COURSE_PLAYER__.getCurrentTime` / `.seekTo` from `player.js`.
5. **Lesson resources** (above notes): two sub-forms — **attach file from disk** (paste a path, absolute or relative to the course folder; nothing is uploaded — the file is read in place via `VideoAttachment::absoluteFilePath()` whenever served) and **add link** (validated URL). List shows each item with a "Open" link (files open inline / download via `response()->file()`; links open in a new tab) and a remove action. Files whose path no longer resolves are rendered with a strikethrough title and a "File missing" hint.
6. **End of video**: optional redirect via `nextUrl` in `__COURSE_PLAYER__`. When the final lesson completes the course, `videos.progress` returns `course_just_completed: true` and the player runs confetti + a “Course complete” toast (`resources/js/confetti.js`, `canvas-confetti`).
7. **Code playground** (`/playground`): server-side runner for **JavaScript, Python, PHP, Go**. `app/Services/LanguageRuntimeProbe.php` probes `node`, `python3`, `php`, `go` via `Symfony\Process` and caches the result for 1h under key `playground.runtimes.v1`; the UI only offers languages whose binary was found, and shows install hints (Homebrew / apt) when none are available. `app/Services/CodeRunner.php` writes `main.{ext}` (plus `go.mod` for Go) to a fresh `storage/app/playground/{uuid}/` per run, executes with an **8 s timeout**, caps stdout/stderr at **256 KB each**, and deletes the temp dir in `finally`. The editor is a textarea with Tab indent and **⌘/Ctrl+Enter** to run; last code per language persists in `localStorage` under `home-teacher-playground-code-{lang}`; last selected language under `home-teacher-playground-last-lang`.
8. **Coding problems** (`/problems`, owner-only — 404 for other users; sharing/groups are intentionally **not** built yet). **Problem** — `title`, `difficulty`, markdown `description`, `tags`, `hints`, optional `reference_solution`/`reference_language`, per-language `starter_code` overrides, `time_limit_ms` (500–8000, default 4000), `compare_mode` ∈ exact / trim_lines (default) / tokens / float (±1e-6). **ProblemTestCase** — `label`, stdin `input`, `expected_output`, `is_hidden`. **ProblemSubmission** — verdict history with per-case `results` JSON. Judging: `app/Services/ProblemJudge.php` runs `CodeRunner` once per case via the lazy `cases()` generator (the controller streams each case as NDJSON, `X-Accel-Buffering: no` so nginx doesn't buffer). Status ∈ accepted / wrong_answer / runtime_error / time_limit (first failing case wins). **Hidden cases return pass/fail + time only — never input, expected, actual or stderr** (stderr could echo the input); keep that covered by tests. Go always gets the runner's max timeout because `go run` compiles on every run. A problem is solved if any submission was accepted; `first_solve` in the `done` event triggers confetti. Editing updates test cases in place by `id` (ids from another problem are ignored) and deletes the rest. `ProblemStarterCode` supplies stdin-reading starter templates.
   - **Solve page** (`resources/js/problems/solve.js`): resizable statement | editor | console panes (layout in `home-teacher-problem-layout`), CodeMirror via `problems/editor.js`, Run (examples or custom stdin) / Submit (⌘/Ctrl+Enter, again = cancel), live case chips, expected-vs-got diff, hints for common mistakes, clickable error lines parsed from stderr, Submissions/Hints/Solution tabs, focus mode (`F`), mobile tab layout. Code persists per problem+language in `localStorage` (`home-teacher-problem-{id}-code-{lang}`), last language in `home-teacher-problem-last-lang`.
   - **Authoring form** (`problems/form.js`): sectioned page with readiness checklist, markdown toolbar + Write/Split/Preview, test-case manager (drag reorder, duplicate, paste-many, undoable delete), reference solution **Check all / Fill empty / Regenerate** (runs against unsaved tests), hints, settings, unsaved-changes guard, ⌘S.
   - **Function mode** (LeetCode-style, default for new problems): `problems.io_mode` ∈ stdin / function, `problems.signature` JSON `{ name, params: [{name,type}], returns }` — 0..8 params, types `int|float|string|bool` plus `[]` / `[][]`. Test `input` = **one minified JSON value per line in parameter order** (empty for zero params), `expected_output` = JSON return value; both canonicalised on save. `App\Support\FunctionSignature` validates/compares (type-strict, float ±1e-6, `unordered` compare mode); `App\Services\FunctionHarness` appends a harness **after** the solver's code (line numbers stay correct), calls `name(...)` or `Solution().name(...)` and prints a random per-run marker + JSON so the solver's own prints are split off (`stdout` in case rows, never for hidden cases). Languages: Python / JavaScript / PHP (harness appended to the code) and **Go**: the solver's code becomes `solution.go` (a missing `package main` is prefixed onto line 1 so line numbers don't shift; a solver `func main` is rejected with a friendly message) and a generated `main.go` harness (`_ht*` names, no builtins solvers redefine, nil slices → `[]`, no HTML escaping). Go is **built once per judging run** via `CodeRunner::compile()` → `CompiledProgram` (shared persistent cache `storage/app/go-build-cache`, `GOTOOLCHAIN=local`, `GOPROXY=off`, `GOWORK=off`, `go.mod` at the installed Go version, `-trimpath`), then each test runs the binary with the problem's normal time limit; a failed build yields a `compile` NDJSON event and verdict `compile_error` (no tests run; compiler output is safe to show). Function names in `FunctionSignature::GO_CONFLICTS` just disable Go for that problem. Stored signatures load with a syntax-only check (reserved words are enforced at save time) so extending the reserved list can't strand old problems. Go stdin problems and the Playground still use the old `go run` path (8 s cap). Go tests need a working `go` on PATH — under a sandboxed shell the snap launcher fails, so run them with `PATH=/snap/go/current/bin:$PATH`. JS harness uses `process.getBuiltinModule('fs')` because the project's `"type": "module"` makes runner files ESM. Client mirror (starter generation, value checks, signature + LeetCode example paste parsers) in `resources/js/problems/signature.js`.
   - Vite entry `resources/js/problems.js` lazy-loads `problems/solve.js` or `problems/form.js`; styles in `resources/css/problems.css`. The Playground still has its own CodeMirror setup (not yet shared with `problems/editor.js`).
