# Home Teacher — agent / continuity notes

This file is the **tracked** copy of project context for new chats (`.cursor/rules/` may be gitignored locally). Point the AI here or keep this open for handoff.

## What this app is

A **Laravel** app to watch **course videos from disk** with **saved progress**, plus a **code Playground** and **LeetCode-style coding problems**. It is **multi-user**: accounts (email/password or Google), an **admin** role, and **invite-only sign-up** by default. Each user's courses, roadmaps, notes, problems and submissions are private to them. It runs on the owner's machine and may be exposed to other people (e.g. through a tunnel), so **treat every signed-in user as untrusted** — see Security.

## Stack

- Laravel 13 (Blade), PHP ≥ 8.3, SQLite, Vite 8, Tailwind CSS v4 (no typography plugin — rendered markdown uses `.note-prose`)
- Laravel Socialite (Google sign-in)
- **Plyr** — `resources/js/player.js` (Vite entry `player`)
- **CodeMirror 6** — problems editor (`resources/js/problems/editor.js`); Sortable.js for drag reordering; canvas-confetti
- CSS: `resources/css/app.css` (courses, theater mode, Plyr overrides), `resources/css/problems.css`
- Code execution: bubblewrap (`/usr/bin/bwrap`) + `prlimit` — required unless `CODE_SANDBOX=none`

## Accounts and access

- **User** — `name`, `email`, `password` (nullable for Google-only), `google_id`, `accent_color`, `is_admin`, `invited_by_id`. `is_admin` is **never mass-assignable** (set with `forceFill`).
- **Ownership:** route model bindings in `AppServiceProvider` resolve `{course}`, `{roadmap}` and `{video}` **only among the current user's records** (404 otherwise). Problems use `authorizeOwner()` in `ProblemController`. Keep new routes scoped the same way.
- **Admins** (the first account ever created; the add-admins migration also promoted the earliest existing account). Only admins can add courses, rescan them, use the folder picker and attach **files by path** — these read the server's disk. Routes are grouped under the `admin` middleware (`App\Http\Middleware\EnsureAdmin`). Admins manage roles at **Profile → Users** (the last admin can't be removed) or with `php artisan app:make-admin email [--remove]`.
- **Sign-up** — `App\Support\Registration`, `REGISTRATION_MODE` = `invite` (default) / `open` / `closed`; the very first account is always allowed. **Invite** (`invites` table): `token`, creator `user_id`, `note`, `max_uses` (null = unlimited), `uses`, `expires_at`, `revoked_at`; `status()` ∈ active / used / expired / revoked. Opening `/invite/{token}` stores the token in the session; the sign-up form **and Google sign-in** both create the account through `Registration::createUser()`, which consumes the invite inside a transaction and sets `invited_by_id`. Members can have ≤ 5 active invites (≤ 10 uses, ≤ 30 days); admins can also create unlimited / never-expiring ones and see all invites (`config/registration.php`).
- **Google sign-in** links to an existing account by email **only when Google reports the email as verified** (`getRaw()['email_verified']`).

## Data model (short)

- **Course** — `user_id`, `title`, `folder_path`, `archived_at`; has many **Video** (`sort_order`)
- **Video** — a "lesson"; `type` ∈ {`video`, `pdf`, `html`} (`Video::TYPE_*`), set by `CourseVideoScanner` from the file extension. `video` lessons play in Plyr and track position; `pdf`/`html` lessons render in an iframe on the watch page (`videos/show.blade.php` branches on `$video->isVideo()/isPdf()/isHtml()`) and have no play position — completion is a manual "Mark as done" toggle (`videos.mark-complete`, `VideoProgressService::setManualCompletion()`). HTML lessons are framed with `sandbox="allow-scripts"` (no `allow-same-origin`) since the file's own script could otherwise run with the viewer's session — do not drop that attribute. `Video::absoluteFilePath()` only resolves files **inside** the course folder.
- **VideoProgress** — per-lesson watch state; `progressPercent()` powers bars (manual-completion lessons are 0 or 100)
- **VideoNote** — `body`, optional `timestamp_seconds` (lesson notes vs time cues)
- **VideoAttachment** — file or link per lesson; `kind` ∈ {`file`, `link`}, `title`, `url`, `file_path`/`mime_type`/`size_bytes`, `sort_order`. **Files are referenced, not uploaded.** `absoluteFilePath()` resolves a path relative to the course folder (no traversal); an **absolute path outside the course folder is only served when the course owner is an admin**. Deleting an attachment leaves the file on disk.
- **Roadmap** — `user_id`, ordered list of the user's courses
- **Problem / ProblemTestCase / ProblemSubmission** — see feature 8
- **Invite** — see Accounts and access

## Routes worth knowing

- Auth: `login` (POST throttled + per-account limits), `register` (POST throttled), `auth.google.redirect|callback`, `invites.accept` (GET `/invite/{token}`)
- Courses: `courses.index`, `courses.show`, `courses.archive|restore|reset-progress`, `courses.videos.reorder` (POST JSON `{ video_ids: number[] }` — full permutation of that course's lessons), `courses.preview.stream`; **admin only:** `courses.create`, `courses.store` (folder must be inside `COURSE_BROWSE_ROOTS`; empty = whole computer), `courses.rescan`, `folder-picker`
- Videos: `videos.show`, `videos.update` (PATCH — rename lesson), `videos.stream`, `videos.progress` (POST JSON, video lessons only), `videos.mark-complete` (POST JSON `{ completed: bool }`, pdf/html lessons)
- Notes: `videos.notes.store` (POST JSON `{ body, timestamp_seconds? }` → `{ message, note: { id, html } }`), `videos.notes.destroy`, `videos.notes.preview` (POST JSON `{ body }` → `{ html }`)
- Attachments: `videos.attachments.store` (POST, `kind=link` with `url` for everyone; `kind=file` with `file_path` **admins only**), `videos.attachments.download` (GET — `response()->file()` from the real on-disk location), `videos.attachments.destroy`
- Roadmaps: `roadmaps.*` resource, `roadmaps.courses.reorder|attach|detach`
- Profile: `profile.account`, `profile.analytics` (watch stats / monthly activity), `profile.notes`, `profile.accent.update`, `invites.index|store|destroy` (Profile → Invites), **admin only:** `admin.users.index|toggle-admin` (Profile → Users)
- Playground: `playground.show`, `playground.run` (POST JSON `{ language, code, stdin? }` → `{ stdout, stderr, exit_code, duration_ms, timed_out, stdout_truncated, stderr_truncated }`; runtime host paths are not exposed), `playground.refresh` (POST — clears the runtime probe and sandbox caches)
- Problems: `problems.*` resource routes (index takes `q`, `status`=todo|attempted|solved, `difficulty`, `tag`, `sort`), `problems.random`, `problems.preview` (POST `{ body }` → `{ html }`), `problems.reference-check` (POST `{ language, code, compare_mode?, time_limit_ms?, tests[], io_mode?, signature? }` → **NDJSON** per-case results for the author's *unsaved* form), `problems.run` (POST JSON `{ language, code, stdin? }` → raw run, no verdict; function problems also return `returned` / `prints`), `problems.run-examples` (POST — **NDJSON** over visible cases, records nothing), `problems.submit` (POST — **NDJSON** `start` / `compile`? / `case`* / `done`; records a `ProblemSubmission`), `problems.submissions.show` (GET JSON incl. code). Run/submit/reference routes are throttled.

## Features (do not break casually)

1. **Course index**: cards show **overall progress** — `Course::aggregateProgressPercent()`. Ordered by **most recent watch activity** (`max(video_progress.updated_at)` per course), then courses with no watch history by title. "Add course" buttons and empty-state links show only for admins; members see an explanation instead.
2. **Course show** (`/courses/{course}`): **course-wide progress bar** + per-lesson list with **drag handle** to reorder (Sortable.js); **rescan** (admins) adds/removes lessons from disk without changing **custom lesson names** (scanner only sets titles for newly discovered files); new files append at the end. Current/next lesson use **index order**, not raw `sort_order` gaps.
3. **Video page**: Plyr, theater (`T`), keyboard shortcuts; **Previous / Next lesson** cards **always** shown; **disabled** style on first/last; neighbors by **order index**.
4. **Lesson notes** under the player: general vs **playhead time**; cues **seek** via `window.__COURSE_PLAYER__.getCurrentTime` / `.seekTo` from `player.js`.
5. **Lesson resources**: **add link** (validated URL, everyone) and, for admins, **attach file from disk** (absolute or relative to the course folder; nothing is uploaded). Each item has "Open" and remove; files whose path no longer resolves show a strikethrough title and "File missing".
6. **End of video**: optional redirect via `nextUrl` in `__COURSE_PLAYER__`. When the final lesson completes the course, `videos.progress` returns `course_just_completed: true` and the player runs confetti + a "Course complete" toast (`resources/js/confetti.js`).
7. **Code playground** (`/playground`): **JavaScript, Python, PHP, Go**. `LanguageRuntimeProbe` probes `node`, `python3`, `php`, `go` and caches the result for 1h (`playground.runtimes.v1`); the UI only offers detected languages and shows install hints otherwise. `CodeRunner::run()` writes `main.{ext}` to a fresh `storage/app/playground/{uuid}/`, runs it **inside the code sandbox** with an **8 s timeout**, caps stdout/stderr at **256 KB each** and deletes the folder in `finally`. Go is built with `CodeRunner::compile()` (sandboxed, shared build cache) and the binary then runs read-only. Last code per language in `localStorage` (`home-teacher-playground-code-{lang}`), last language in `home-teacher-playground-last-lang`; ⌘/Ctrl+Enter runs.
8. **Coding problems** (`/problems`, owner-only — 404 for other users; **sharing between users is planned but not built**). **Problem** — `title`, `difficulty`, markdown `description`, `tags`, `hints`, optional `reference_solution`/`reference_language`, per-language `starter_code` overrides, `time_limit_ms` (500–8000, default 4000), `compare_mode`, `io_mode`, `signature`. **ProblemTestCase** — `label`, `input`, `expected_output`, `is_hidden`. **ProblemSubmission** — verdict history with per-case `results` JSON. Judging: `ProblemJudge::cases()` is a lazy generator (one run per case, streamed as NDJSON with `X-Accel-Buffering: no`). Status ∈ accepted / wrong_answer / runtime_error / time_limit / compile_error (first failing case wins). **Hidden cases return pass/fail + time only — never input, expected, actual, stdout or stderr** (stderr could echo the input); keep that covered by tests. A problem is solved if any submission was accepted; `first_solve` in `done` triggers confetti. Editing updates test cases in place by `id` (ids from another problem are ignored) and deletes the rest.
   - **Stdin mode**: input on stdin, stdout compared with `compare_mode` ∈ exact / trim_lines (default) / tokens / float (±1e-6). `ProblemStarterCode` supplies stdin-reading templates. Go stdin problems still get the runner's 8 s maximum per test (`timeoutFor(..., compiled: false)`).
   - **Function mode** (LeetCode-style, default for new problems): `signature` JSON `{ name, params: [{name,type}], returns }` — 0..8 params, types `int|float|string|bool` plus `[]` / `[][]`. Test `input` = **one minified JSON value per line in parameter order** (empty for zero params), `expected_output` = JSON return value; both canonicalised on save. `compare_mode` ∈ exact / unordered (top-level list in any order); floats always ±1e-6. `App\Support\FunctionSignature` validates and compares (type-strict); stored signatures load with a **syntax-only** check (reserved words are enforced at save time) so extending `RESERVED` can't strand old problems. `App\Services\FunctionHarness` appends a harness **after** the solver's code (line numbers stay correct), calls `name(...)` or `Solution().name(...)`, and prints a random per-run marker + JSON so the solver's own prints are split off (`stdout` in visible case rows). Python / JavaScript / PHP get the harness appended; the JS harness uses `process.getBuiltinModule('fs')` because `"type": "module"` makes runner files ESM. **Go**: the solver's code becomes `solution.go` (a missing `package main` is prefixed onto line 1; a solver `func main` is rejected with a friendly message) plus a generated `main.go` (`_ht*` names, avoids builtins solvers redefine, nil slices → `[]`, no HTML escaping), **built once per judging run** (`CodeRunner::compile()` → `CompiledProgram`; `GOTOOLCHAIN=local`, `GOPROXY=off`, `GOWORK=off`, `go.mod` at the installed version, `-trimpath`), then each test runs the binary with the problem's normal limit. A failed build emits a `compile` event and `compile_error` (no tests run; `FunctionHarness::explainGoCompile()` adds a friendly hint). Names in `FunctionSignature::GO_CONFLICTS` just disable Go for that problem. The client mirror (starter generation, value checks, signature + LeetCode example paste parsers) is `resources/js/problems/signature.js`.
   - **Solve page** (`resources/js/problems/solve.js`): resizable statement | editor | console panes (layout in `home-teacher-problem-layout`), Run (examples or custom input — per-parameter fields for function problems) / Submit (⌘/Ctrl+Enter, again = cancel), live case chips, expected-vs-got diff, hints, "Go to line" from stderr / Go compiler output, Submissions/Hints/Solution tabs, focus mode (`F`), mobile tabs. Code persists per problem+language (`home-teacher-problem-{id}-code-{lang}`), last language in `home-teacher-problem-last-lang`.
   - **Authoring form** (`resources/js/problems/form.js`): sectioned page with readiness checklist, markdown toolbar + Write/Split/Preview, **Input format** section (function signature builder with live starter preview per language, paste-a-signature), test-case manager (per-parameter fields in function mode, drag reorder, duplicate, paste-many incl. LeetCode `Input:/Output:` blocks, undoable delete), reference solution **Insert stub / Check all / Fill empty / Regenerate** (runs against unsaved tests), hints, settings, unsaved-changes guard, ⌘S.
   - Vite entry `resources/js/problems.js` lazy-loads `problems/solve.js` or `problems/form.js`. The Playground still has its own editor setup (not shared with `problems/editor.js`).

## Security (read before touching code execution, auth or files)

- **Every program run for a user goes through `App\Services\CodeSandbox`** (bubblewrap): Playground, problem run/submit, reference checks and Go builds. Inside: read-only `/usr`, the language runtime read-only at `/opt/<lang>` (nvm Node, the Go snap…), the run folder at `/work` (read-only except during the Go compile step), a 16 MB private `/tmp`; **no network, no app files, no host home directories, no other processes, none of the app's environment variables** (`--clearenv`). Limits (`config/sandbox.php`): memory (data segment; Node gets more address space plus `--max-old-space-size`), 64 processes (applied *inside* the sandbox — `RLIMIT_NPROC` outside counts all of the user's processes), 16 MB file size, open files, CPU seconds; everything dies with the run. Go compiles in a separate sandbox with the shared cache mounted at `/cache`; test runs never see the cache.
- **Fails closed:** `CODE_SANDBOX=bwrap` (default) refuses to run code when bubblewrap doesn't work (reason logged; failure cached 60 s). `CODE_SANDBOX=none` runs code directly — only for a private, single-user machine; the environment is still scrubbed (`CodeSandbox::scrubbedEnv()`), because Symfony Process otherwise hands the app's `.env` secrets to child processes.
- **Disk access** is admin-only (see Accounts and access): courses, rescans, the folder picker and file attachments by path.
- **Login** is rate-limited per account (10/min) and per account+IP (5/min); `POST /login` and `/register` are also throttled per IP.
- **Proxies:** `TRUSTED_PROXIES` (default `127.0.0.1,::1` — a local tunnel or reverse proxy) decides whose `X-Forwarded-*` headers are believed (`App\Http\Middleware\TrustProxies`, read from config at request time). `*` lets anyone fake their IP or https.
- **Headers / cookies:** `SecurityHeaders` middleware sends `X-Frame-Options: SAMEORIGIN`, `nosniff`, a referrer policy and a permissions policy (HSTS only on https in production), and marks the session cookie Secure on real https requests unless `SESSION_SECURE_COOKIE` says otherwise.
- **Before other people can reach the site**, run `php artisan app:security-check` (exits non-zero on blocking problems) and set `APP_DEBUG=false`, `APP_ENV=production`, an `https://` `APP_URL`, ideally `COURSE_BROWSE_ROOTS`, and use a real web server (php-fpm + nginx/Caddy, or `PHP_CLI_SERVER_WORKERS`) instead of `php artisan serve`.

## Testing

- `php artisan test`. Security suites: `CodeSandboxTest` (escape attempts print only blocked/EXPOSED, never contents), `SecurityHardeningTest`, `AccessControlTest`. Problems: `ProblemTest`, `ProblemFunctionModeTest`.
- Tests needing a runtime skip when it isn't detected. Go tests need a working `go` on PATH — inside a sandboxed shell the snap launcher (`/snap/bin/go`) fails, so run `PATH=/snap/go/current/bin:$PATH php artisan test`.
- Sandbox tests skip if bubblewrap isn't usable in the test environment.

## After clone / pull

`composer install`, `php artisan migrate`, `npm ci` or `npm install`, `npm run build` (or `npm run dev`). Install bubblewrap (`apt install bubblewrap`) or code won't run. The first account you create becomes the admin.

Do not commit `.env`.
